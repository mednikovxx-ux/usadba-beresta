# Бронирование — контракт API для CRM

Форма на сайте (`js/booking.js`) уже собирает и проверяет заявку. Чтобы подключить CRM,
достаточно поднять два метода и указать их адреса в `BOOKING_CONFIG` в начале `js/booking.js`
(или задать `window.BERESTA_BOOKING = { … }` до подключения скрипта):

```js
availabilityUrl: '/api/availability',
bookingsUrl:     '/api/bookings',
```

Пока `bookingsUrl: null` — работает **демо-режим**: заявки сохраняются только в браузере
посетителя (`localStorage`, ключ `beresta_bookings`) и **до владельца не доходят**.

---

## GET `/api/availability?from=YYYY-MM-DD&to=YYYY-MM-DD`

Занятые ночи в диапазоне. Ночь обозначается датой заезда: бронь 12→15 ноября занимает ночи 12, 13, 14.
День выезда (15) свободен для нового заезда.

```json
{
  "busy": ["2026-11-12", "2026-11-13", "2026-11-14"],
  "minNights": 1,
  "pricePerNight": 9000
}
```

`minNights` и `pricePerNight` — необязательны. Если цена передана, сайт сам посчитает сумму.

## POST `/api/bookings`

Тело (JSON), которое отправляет сайт:

| Поле | Тип | Пример |
| --- | --- | --- |
| `checkIn` | дата | `"2026-11-12"` |
| `checkOut` | дата | `"2026-11-15"` |
| `nights` | число | `3` |
| `guests` | число | `2` |
| `name` | строка | `"Анна"` |
| `phone` | строка, E.164 | `"+79000000000"` |
| `email` | строка или null | `"anna@mail.ru"` |
| `services` | массив | `["sauna", "tub"]` |
| `comment` | строка или null | `"Приедем с собакой"` |
| `consent` | true | согласие на обработку ПДн |
| `source` | строка | `"site"` |
| `page` | URL | страница, с которой отправлено |
| `utm` | объект | `{ "utm_source": "yandex" }` |
| `createdAt` | ISO-время | `"2026-10-27T12:00:00.000Z"` |

Ответы:
- `201` — `{ "id": "…", "status": "new" }` — сайт покажет «Заявка принята».
- `409` — даты уже заняты: сайт попросит выбрать другие и перезагрузит календарь.
- другое — сайт покажет ошибку и предложит позвонить.

**Сервер обязан сам перепроверить**, что даты свободны (между открытием страницы и отправкой их могли занять),
и валидировать поля — проверка в браузере только для удобства гостя.

## Что предусмотреть в CRM

- Статусы заявки: `new` → `confirmed` / `cancelled`, после выезда — `completed`.
- Подтверждённые брони попадают в `busy` для календаря на сайте.
- Уведомление владельцу о новой заявке (Telegram-бот или почта).
- Хранение персональных данных — по 152-ФЗ; ссылка на политику — в форме.
